1. Executive Summary

During integration testing of the Seeed Studio XIAO ESP32-C6 with the Android Client over direct USB-C OTG, the drone receiver remains in Airborne Failsafe because exactly 0 bytes are received from the mobile application.

A source code audit of the Android repository revealed that the protocol structures (EspIcdCommanderPacket, Cobs, Crc16Ccitt) are mathematically correct according to ICD SPEC-REV 2.4. However, four critical implementation defects in device enumeration, USB interface claiming, and packet dispatching completely prevent the Android app from opening the USB port or transmitting any bytes to the ESP32.

3. Detailed Defect Analysis & Remediation

Defect 1: Hardcoded Crazyradio VID / PID Filter in USB Discovery

Root Cause: MainActivity.isCrazyradioAvailable() specifically scans for Nordic Crazyradio VID 0x1915 and PID 0x7777. Because Seeed Studio XIAO ESP32-C6 has VID 0x2886 (Seeed) or 0x303A (Espressif) and PID 0x0048 / 0x1001, discovery returns an empty list.

When the user presses the "Connect" button, the app evaluates isCrazyradioAvailable() == false, branches to connectBlePreChecks(), displays a toast "USB OTG is the sole supported transport link.", and terminates without attempting to open USB.

Recommended Patch in MainActivity.java: 
- List<UsbDevice> usbDeviceList = UsbLinkAndroid.findUsbDevices(usbManager, (short) Crazyradio.CRADIO_VID, (short) Crazyradio.CRADIO_PID);
+ // Accept Seeed Studio (0x2886) and Espressif (0x303A) or any connected USB CDC device
+ List<UsbDevice> usbDeviceList = UsbLinkAndroid.findEspOrCrazyDevices(usbManager);
  return !usbDeviceList.isEmpty();
Defect 2: USB CDC-ACM Multi-Interface & Endpoint Enumeration Bug

Root Cause: Under standard USB Communications Device Class (CDC ACM):

  • Interface 0 (Class 2, CDC Control): Contains only 1 Interrupt IN endpoint for status signals.
  • Interface 1 (Class 10, CDC Data): Contains 2 Bulk endpoints (Bulk IN & Bulk OUT).
UsbLinkAndroid.java explicitly hardcodes: 
mIntf = this.mUsbDevice.getInterface(0);
if (mIntf.getEndpointCount() < 2) {
    Log.e(LOG_TAG, "Could not find endpoints");
    return;
}
Because Interface 0 on ESP32-C6 has only 1 endpoint, this check fails 100% of the time, logging an error and aborting before claiming the interface or opening endpoints.

Recommended Patch in UsbLinkAndroid.java: 
- mIntf = this.mUsbDevice.getInterface(0);
- if (mIntf.getEndpointCount() < 2) { Log.e(LOG_TAG, "Could not find endpoints"); return; }
+ // Search across all device interfaces for the CDC Data interface with Bulk IN and Bulk OUT
+ UsbInterface dataInterface = null;
+ for (int i = 0; i < mUsbDevice.getInterfaceCount(); i++) {
+     UsbInterface iface = mUsbDevice.getInterface(i);
+     UsbEndpoint in = null, out = null;
+     for (int j = 0; j < iface.getEndpointCount(); j++) {
+         UsbEndpoint ep = iface.getEndpoint(j);
+         if (ep.getType() == UsbConstants.USB_ENDPOINT_XFER_BULK) {
+             if (ep.getDirection() == UsbConstants.USB_DIR_IN) in = ep;
+             if (ep.getDirection() == UsbConstants.USB_DIR_OUT) out = ep;
+         }
+     }
+     if (in != null && out != null) { dataInterface = iface; mEpIn = in; mEpOut = out; break; }
+ }
+ if (dataInterface == null) { throw new IOException("No bulk data interface found"); }
+ mIntf = dataInterface;
Defect 3: Packet Pipeline Bypass (toCobsUsbFrame & bulkWrite Never Called)

Root Cause: Commit 6365c77 created EspIcdCommanderPacket.toCobsUsbFrame() and UsbLinkAndroid.bulkWrite(), but failed to connect them to the joystick transmission loop.

In MainPresenter.startSendJoystickDataThread(): 

EspIcdCommanderPacket icdPacket = new EspIcdCommanderPacket(...);
sendPacket(icdPacket); // Invokes mCrazyflie.sendPacket()
In Crazyflie.java: 
public void sendPacket(CrtpPacket packet) {
    if (mDriver.isConnected()) { // Evaluates to FALSE! No Crazyradio dongle attached
        mDriver.sendPacket(packet);
    }
}
Because mDriver is an uninitialized RadioDriver, all packets are dropped silently. toCobsUsbFrame() is never called, and no bytes are ever written to USB.

Recommended Patch in MainPresenter.java: 
  EspIcdCommanderPacket icdPacket = new EspIcdCommanderPacket(
          rollNorm, pitchNorm, yawNorm, thrustNorm,
          aux1, aux2, aux3, aux4, aux5
  );
- sendPacket(icdPacket);
+ // Direct USB-CDC Transmission according to ICD SPEC-REV 2.4
+ if (mUsbLink != null && mUsbLink.isUsbConnected()) {
+     byte[] usbFrame = icdPacket.toCobsUsbFrame();
+     mUsbLink.bulkWrite(usbFrame);
+ }
Defect 4: Telemetry Listener Disconnected from UI Dashboard

Root Cause: UsbLinkAndroid includes a background reader thread that successfully parses 6-byte telemetry (0x51) and invokes mTelemetryListener.onTelemetryReceived(...). Additionally, MainActivity.updateTelemetry(...) was implemented to display live voltage and PPS.

However, usbLink.setTelemetryListener(...) is never called during initialization. As a result, even after downlink frames are fixed, the uplink telemetry from the ESP32 will not update the phone screen.

Recommended Fix: In MainActivity.java or MainPresenter.java, register the listener upon establishing the connection: 
mUsbLink.setTelemetryListener(new UsbLinkAndroid.TelemetryListener() {
    @Override
    public void onTelemetryReceived(int voltageMv, int currentMa, int pps) {
        mainActivity.updateTelemetry(voltageMv, currentMa, pps);
    }
    @Override
    public void onWatchdogTimeout() {
        mainActivity.setLinkQualityText("LOST");
    }
});

4. Verification & Validation Protocol

Once the Android team implements the four fixes above, verify the link end-to-end using the following steps:

  1. Connect XIAO ESP32-C6 to the Android phone via USB OTG cable.
  2. Ensure Android prompts for "Allow app to access USB device" and grant permission.
  3. Open the app and observe the built-in LED on GPIO 15:
    • Cutoff (Throttle = 1000 µs): LED is completely OFF.
    • Mid Throttle (Throttle = 1500 µs): LED glows at ~25% brightness.
    • Full Throttle (Throttle = 2000 µs): LED glows at 100% full brightness.
  4. Connect phone browser to Wi-Fi XIAO-C6-DEBUG at http://192.168.4.1 to confirm 50 PPS throughput and zero CRC errors.
